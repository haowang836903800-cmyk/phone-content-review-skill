## 不是一个“已跑通”就能放进任何脚本

分四步看：**表里说能做什么 → 实测具体做到了哪一步 → 是否允许本轮推广 → 这个达人自己的样机是否复现。**

状态是线索，结果和失败环节是边界。字段空白不是自动可推；“已跑通＋可推 pending”不是发布许可。来源更新时间、App、入口、素材变了，要重新试。下面的“需补证”是本次审核判断，不回写测试状态。

## 小程序专项与 App 操作别混在一起

小程序专项有“围绕同一件事，先问/比较/规划，再让小程序承接”的要求；城市、服务、入口和付款确认按实际支持范围。拍一个 App 自动打开，不自动等于完成了这个专项。日常充值、缴费、还款等只展示实际支持步骤，不能预设全部读屏、代填、代付都可完成。

## 一个可直接复用的实测记录

| 字段 | 怎么填 |
|---|---|
| 日期、设备、系统、App 版本 | 保留可复现条件 |
| 起始页面和输入 | 原图/清单/录音、任务、预算/时间等约束 |
| 实际步骤 | 手机做了哪些；本人在哪一步解锁、补信息、选项或付款 |
| 结果 | 真实文件/订单状态/清单/设置，不用一句“成功了”代替 |
| 失败与重试 | 第几步失败；如何修正；是否仍有没做成的部分 |
| 人工核对 | 日期、数字、规格、接收人等逐项正确 |
| 可拍内容 | 只写已有证据支持的部分；待测组合另列 |

把不支持、需要接管、只完成一部分也记录下来。它们能让脚本更真实，也能避免拍完才发现主张没有证据。
