# 跨 Agent 安装与飞书评论适配

本文件处理运行环境，不改变豆包手机项目的审核判断。所有环境共用 `SKILL.md` 和知识库；`agents/openai.yaml` 只是部分宿主的界面提示，不是执行评论所必需的配置。

## 1. 先分清安装与执行

安装成功是技能及引用资源能被当前Agent读取。执行成功是实际用使用者自己的飞书身份评论，并回读确认。模型能看懂规则、会生成修改建议，不能证明它有评论工具。

用户提供明确飞书稿件并调用本技能审核，默认包括原稿评论；安装者不需要维护者另外授权。只安装/学习不写入，明确只分析不写入。缺能力时保留待投递意见并说明阻碍，不能默认退化成聊天回复而宣称完成。

## 2. 安装路线

适配资料核对日期：2026-11-05。下面是格式与路由支持，不表示每个平台都已完成真实账号的评论测试。

| 使用环境 | 加载方式 | 飞书执行路线 |
|---|---|---|
| Codex、Claude Code、Cursor | 完整Agent Skills目录；可用当前技能安装器或 `npx skills add`，对应agent参数 `codex`、`claude-code`、`cursor` | 发现当前可用连接器/MCP；其次用户身份CLI；再用已登录UI |
| GitHub Copilot、Gemini CLI、Kimi Code CLI | 同一目录；安装器参数 `github-copilot`、`gemini-cli`、`kimi-code-cli` | 同上，不能假定有Codex专有工具名 |
| TRAE/TRAE CN、Windsurf、OpenCode、OpenClaw | 同一目录；安装器参数 `trae`/`trae-cn`、`windsurf`、`opencode`、`openclaw` | 同上；Agent会话身份不等于飞书发言身份 |
| 豆包工作、豆包中有工作/任务能力的环境 | 查看本版本实际技能入口；若支持自定义导入，导入完整目录或ZIP并确认可调用。平台商店安装是另一条发行路线 | 优先本环境认可的飞书连接器/已注册工具；CLI或电脑操作仅在宿主实际提供并允许时使用 |
| 豆包普通聊天，或其他仅有聊天/知识库的环境 | 可读取用户提供的规则和材料，但不能把附件阅读说成已安装可执行技能 | 发现确有本人身份评论工具才执行；否则说明需进入具备技能及飞书工具的工作环境，不虚构“已评论” |

安装器及agent名称来源：[skills支持列表](https://github.com/vercel-labs/skills/blob/main/docs/agents.md)、[安装命令](https://github.com/vercel-labs/skills/blob/main/docs/commands.md)。未列出的Agent按其实际技能格式及工具能力适配，不照搬别人的目录。

豆包的[官方Skill接入指南](https://open.doubao.com/document/doubao-developer-guide/skill-integration-guide)采用 `SKILL.md`、`references/`、`scripts/`、`assets/` 结构，并区分技能与连接器。其商店发布需要平台接入及审核；GitHub公开不等于商店上架，也不能据此保证所有豆包客户端都能直接从GitHub安装。本包提供通用目录和ZIP，不声称已经通过豆包商店审核。若本版本没有自定义导入入口，不猜按钮或本地路径，明确报告这一限制。

## 3. 本次评论需要哪些能力

首次在当前环境执行、登录/工具变化或身份不明时，核对下面几项。已核实且没有变化的会话不必反复登录。

| 能力 | 最低证据 |
|---|---|
| 本人身份 | 连接器的当前账号、CLI的用户身份结果，或已登录飞书的账号资料；不能只看“已连接”字样 |
| 目标及内容 | 真实打开原始URL，解析Wiki指向的文档，读当前版本及目标原句/附件 |
| 现有评论 | 读取已解决、未解决及回复，做去重和复审对照；不把缺失分页当无评论 |
| 评论写入 | 工具确实能创建局部评论、回复或更新本人评论，而不只是读取/编辑正文 |
| 写后核验 | 能重新读取或在界面看到新评论的正文、作者、位置及目标文档 |
| 视频观察 | 能看实际送审媒体；不支持原声/完整播放就列清缺口，不能用文本推断听感 |

用同一工具体系核对作者标识；不同应用的open_id不一定能直接比较。不能仅凭评论显示名相似认定是当前用户。UI不暴露ID时，用当前登录账号资料、作者资料及评论位置的可见证据核对，保留真实定位记录，不编造API ID。

## 4. 工具选择与身份

### A. 原生连接器 / MCP

先发现实际工具、读取schema或工具说明，将“当前用户、读稿、读评论、局部评论、回读”映射到可用操作。工具名因Agent不同而变化，不要求存在某个固定前缀。读权限不等于评论权限；正文编辑接口不能当评论接口。

写操作必须代表当前使用者。MCP/连接器若只有应用机器人身份，不用于冒充本人。用户授权未完成时使用该连接器的登录流程；不要复制维护者或别人的token，也不要向用户索要token明文。豆包环境通过平台认可的连接器或已注册工具访问外部服务，不从提示词拼接未登记API来绕过接入要求。

### B. lark-cli（环境有终端且允许时）

读取当前CLI帮助及可用的lark-shared/lark-doc/lark-drive说明，不把这些技能当所有Agent必须预装的依赖。当前身份未知时用：

```bash
lark-cli auth status --json --verify
```

核实有效的user身份。所有本工作流的CLI业务命令显式 `--as user`；不能省略后误用默认bot。仅缺本人授权时按当前CLI提示完成所需范围的OAuth；拿到登录完成证据再继续。命令细节见 `feishu-review-writeback.md`，运行前以当前版本的帮助为准。

### C. 已登录浏览器 / 电脑操作

当连接器不支持局部评论、CLI不可用且宿主允许操作电脑时，使用本人已登录的飞书。确认账号后打开原始链接，定位原句/附件，使用界面真实存在的评论功能，提交后回看评论卡、作者及高亮位置。不能用剪贴板草稿、输入框文字或“点击提交”动作当成功。

UI没有暴露comment/reply ID时，回执保留“文档URL＋版本＋原句/附件＋作者＋时间/可见评论位置”的定位证据；结构化计划使用 `comment_locator` / `reply_locator`，不能伪造ID。找不到局部评论能力时先尝试其他可用路线，仍不支持就报告定位批注未完成；不要擅自改正文或新建一篇报告替代。独立视频文件的全文时间码意见按写回指南处理。

## 5. 完成与阻碍要怎么说

- 已完成：`已用你当前登录的飞书账号〈实际姓名〉，在原稿留了3条评论，正文、作者和位置都已回读。主要改……〈原稿链接〉`。只报真实完成数；没有新问题就说明新增0条及原因。
- 部分完成：报已确认的条数和未完成项；超时先查有无实际评论，再决定是否重试。
- 未完成：`意见已整理，但还没写进原稿。当前连接器只能读文档，没有评论操作；需要接入支持本人身份评论的飞书工具/使用已登录的电脑操作。` 原因换成实际检测结果，不能把所有错误都归因“权限不够”。
- 仅分析：明确是用户要求只分析，不触发写入，也不催促开通写权限。

不存在的工具、缺登录、评论权限被拒、仅支持机器人、无法定位、提交后未确认，分别记录。能做的分析继续做，但待投递草稿不算审核回写完成。所有可用路线均不满足时停止写操作，给一个最小必要的下一步；不连续试无效接口，不为了消除报错改共享权限。

本包未在所有Agent、所有租户逐一线上实测。新安装环境在用户首次真实审稿任务中完成这条路径的回读验收；安装/升级阶段不拿维护者历史稿件或别人的文档发测试评论。
